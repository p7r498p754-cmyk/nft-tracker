# Тестовый перенос Stars на Cloudflare

Worker nft-tracker-stars-staging обрабатывает тестовые платежи Telegram и сохраняет квитанции в отдельной базе D1. Вызовы Bot API направляются на путь /test/. В тестовом боте доступны /start, /buy PLUS, /buy PRO, /buy ULTRA и /subscription. Оплаченный в тестовой среде доступ действует 30 дней. Возврат отзывает доступ.

Токен отдельного бота, созданного через BotFather на тестовом сервере Telegram, задаётся как секрет TELEGRAM_TEST_BOT_TOKEN. Плановое задание проверяет username, сохраняет вебхук при совпадении имени и проверяет ответ Telegram. Для сообщений Telegram требуется секрет STAGING_WEBHOOK_SECRET, заданный при регистрации вебхука. База подключена как LEDGER, схема живёт в stars-staging.sql. GET /health показывает доступность базы и готовность вебхука. Диагностические маршруты для искусственных событий доступны локальным тестам при STAGING_FIXTURES=1.

Локальная проверка на Node.js 24: `node --test cloudflare/stars-staging.test.mjs`. Тест проходит через HTTP-обработчик и SQLite, а Bot API заменяется управляемой заглушкой. Проверяются неправильный секрет, подмена суммы или пользователя, повтор квитанции, возврат, проверка имени бота и выпуск инвойса через /test/.

Перед переключением основного бота нужны сквозной прогон на тестовом сервере Telegram, интеграция оплаченного доступа с мониторингом, проверка резервного восстановления и канал поддержки покупателей.

Режим STAGING_TELEGRAM_MODE=ordinary-preview позволяет открыть демонстрационный счёт у отдельного бота в обычном Telegram. При подтверждении счёта Worker отвечает отказом и не записывает оплату или доступ. Bot API допускает в этом режиме только отказ на запрос оформления. Для сквозного теста с выдачей пробного тарифа используется отдельный тестовый сервер.
