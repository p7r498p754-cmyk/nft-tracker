# Stars и подарки в NFT Tracker

Проверено по официальной документации 24 ноября 2026 года. Операции со Stars для этого исследования не проводились.

## Вывод для владельца

Telegram поддерживает платный доступ к цифровому сервису за Stars. Условия для разработчиков описывают рекламу своего приложения, увеличение лимита рассылки и программу вознаграждений. В этих условиях мы не нашли прямого разрешения получать вознаграждение владельца отправкой подарков самому себе с последующей перепродажей. Для NFT Tracker такой сценарий остаётся выключенным. Получение персонального разъяснения Telegram нужно до решения о его внедрении. [Условия платформы, раздел 6.2](https://telegram.org/tos/bot-developers#6-2-accepting-payments-in-stars)

| Вопрос | Что подтверждено |
|---|---|
| Где учитывается оплата подписки | Stars за цифровой сервис учитываются на балансе бота. Баланс смотрит владелец, а бот может запросить его через getMyStarBalance. История доступна через getStarTransactions. Это отдельный счёт от личного или подключённого бизнес-аккаунта. [Баланс и операции](https://core.telegram.org/bots/api#getmystarbalance) |
| Какие подарки доступны боту | getAvailableGifts возвращает доступный каталог. sendGift принимает идентификатор доступного подарка и получателя. Ограниченные подарки нельзя направлять каналам. Telegram прямо указывает, что получатель подарка от бота не может конвертировать его обратно в Stars. [Отправка подарка](https://core.telegram.org/bots/api#sendgift) |
| Можно ли оплатить улучшение | Параметр pay_for_upgrade позволяет оплатить улучшение из баланса бота, если подарок допускает улучшение. Предоплата покрывает операцию получателя. Обычный подарок, уникальный коллекционный подарок и актив, выведенный в блокчейн, представляют разные состояния. [Bot API](https://core.telegram.org/bots/api#sendgift) · [Улучшение](https://core.telegram.org/api/gifts) |
| Покупка существующего коллекционного лота | Пользовательский Telegram API описывает resale-инвойс. Для чтения списка перепродажи метод payments.getResaleStarGifts доступен только пользователям. Публичный Bot API не документирует аналогичную покупку произвольного лота с баланса бота. [Список лотов](https://core.telegram.org/method/payments.getResaleStarGifts) · [Покупка при перепродаже](https://core.telegram.org/api/gifts#reselling-collectible-gifts) |
| Передача и продажа | Для конкретного уникального подарка действуют его ограничения, сроки доступности передачи и перепродажи, иногда плата за передачу. Валюта продажи может быть ограничена. Доступный к продаже подарок владелец может выставить по разрешённой платформой цене. Полученная сумма зависит от параметров платформы. Покупатель и выручка не гарантированы. [Правила подарков](https://core.telegram.org/api/gifts) |
| Ограничения выручки | Telegram допускает удержания и списания, в том числе по возвратам. До доступности для рекламы или вознаграждений может пройти до 21 дня. Условия также устанавливают срок действия заработанных Stars в три года. Баланс API нельзя выдавать за сумму к немедленному выводу. [Условия, §§6.2.2–6.2.7](https://telegram.org/tos/bot-developers) |
| Кому достаются Stars после продажи | Вторичная продажа учитывается у соответствующего продавца по правилам маркетплейса. Возможность перепродажи подходящего личного подарка не доказывает разрешённость маршрута вывода выручки бота. Методы подключённого бизнес-аккаунта требуют соответствующих прав и используют баланс соответствующего аккаунта. [Подарки](https://core.telegram.org/api/gifts) · [Business Bot API](https://core.telegram.org/bots/api#getbusinessaccountstarbalance) |
| Разрешённые варианты владельца | Вариант внутри Telegram — использовать подходящий баланс для рекламы собственного сервиса. Это продвижение, а не личный доход. Официальная программа вознаграждений использует Fragment и зависит от доступности, применимых правил и требований к участнику. Проверки возраста, личности и территории сохраняются. [Условия разработчиков](https://telegram.org/tos/bot-developers) |

## Подписки

Для периодического инвойса Telegram документирует createInvoiceLink с XTR, одним элементом prices, пустым provider_token и subscription_period 2592000. Бот обязан проверить заказ и ответить на pre_checkout_query в течение 10 секунд. Выдача доступа допустима после successful_payment. Хранятся идентификатор списания и subscription_expiration_date. Платформа допускает параллельные подписки одного пользователя, поэтому контроль перекрытия периодов нужен приложению. Для возврата Telegram документирует refundStarPayment, для управления будущим продлением — editUserStarSubscription. Продакшен-обработчики финансовых операций в этом выпуске отключены. [Оплата цифровых товаров](https://core.telegram.org/bots/payments-stars) · [Подписки](https://core.telegram.org/api/subscriptions) · [Методы Bot API](https://core.telegram.org/bots/api#createinvoicelink)

## Проект ручной операции после отдельного согласования

У владельца должен быть экран предварительного просмотра с получателем, ID подарка, доступностью, стоимостью улучшения и итогом в Stars. Сервер перепроверяет владельца, наличие подарка и сумму непосредственно перед подтверждением. Для каждого намерения нужна уникальная запись с коротким сроком действия, однократным подтверждением и переходом в состояние исполнения до внешнего вызова. При тайм-ауте результат считается неизвестным до сверки с историей Telegram. Автоматический повтор sendGift опасен двойным расходом: документированного ключа идемпотентности у метода нет. Кнопок отправки и вызовов этого метода в NFT Tracker нет. [Параметры sendGift](https://core.telegram.org/bots/api#sendgift)
