# Постоянный запуск основного бота

Этот профиль предназначен для уже доступного бесплатного Linux-хоста с systemd, Python 3.11+ и постоянным диском. Установка профиля сама по себе не предоставляет хостинг. Команды и мониторинг работают в одном процессе с отдельным потоком для рынка.

1. Поместите проверенную версию в /opt/nft-tracker. Каталог кода принадлежит администратору. Установите nft-tracker.service в /etc/systemd/system/.
2. В /etc/nft-tracker.env с правами 0600 задайте TELEGRAM_BOT_TOKEN, PORTALS_API_KEY и OWNER_CHAT_ID. Задайте DB_PATH=/var/lib/nft-tracker/tracker.sqlite3, STARS_SUPPORT=nishjta и STARS_TERMS_URL=https://github.com/p7r498p754-cmyk/nft-tracker/blob/main/docs/stars-purchase-terms.md. Для проверки владельцем используйте PUBLIC_USERS=0 и STARS_PAYMENTS=0.
3. До переключения перенесите действующую SQLite через приватную резервную копию, проверив восстановление. Не помещайте базу в git. Для резервирования работающей SQLite используйте python3 -m nft_tracker.backup SOURCE NEW_DESTINATION. Храните копию на отдельном приватном носителе.
4. После установки версии workflow с PRIVATE_HOST_ACTIVE задайте эту переменную репозитория равной 1. Дождитесь завершения активного monitor. Проверьте отсутствие другого получателя обновлений Telegram. При действующем webhook переход на polling требует отдельного согласованного переключения.
5. Выполните systemctl daemon-reload и systemctl enable --now nft-tracker. Проверьте /start, кнопки, свежесть рынка и восстановление настроек после перезапуска. Только после сквозной тестовой оплаты и проверки предоставления тарифа включайте PUBLIC_USERS=1 и STARS_PAYMENTS=1 с перезапуском службы.
6. При сбое остановите службу, сохраните приватную базу с подтверждёнными платежами. Возвращайте GitHub polling только после остановки частного получателя. GitHub Actions не должен обрабатывать реальные платежи или получать копию платёжной базы.

Для локальной проверки свежести Portals используйте окружение службы и команду `python3 -m nft_tracker.health`. Код 0 означает, что в существующей базе есть свежий успешный цикл. Проверка не обращается к Telegram, не отправляет сообщения и не измеряет доступность интерфейса.

Для обновления остановите службу, сделайте приватную копию и сохраните идентификатор предыдущего коммита. После запуска проверьте доступ существующего пользователя и свежесть цикла. При откате кода сначала остановите службу и сделайте ещё одну копию: в ней могут быть платежи с момента обновления. Возвращайтесь к предыдущему коду только при совместимости с текущей схемой. Старая копия базы годится для проверки в отдельном каталоге; перед заменой платёжной базы требуется сверка новых операций с Telegram.

Для полного возврата покупатель сообщает поддержке номер квитанции из /payments. Владелец использует /admin refund НОМЕР, сверяет тариф, сумму и номер и отдельно подтверждает операцию кнопкой. При неопределённом результате резерв запроса сохраняется: сверяйте историю Stars перед ручным разрешением спорного платежа. Реальный возврат этим релизом не выполнялся.
